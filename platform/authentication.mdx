Pravidhi supports authentication at two boundaries: the application/control-plane boundary and the remote MCP resource-server boundary.

## MCP OAuth

The production MCP resource server is:

```
https://mcp.pravidhisolutions.in/mcp
```

The authorization server is the Pravidhi Keycloak realm:

```
https://mcp.pravidhisolutions.in/auth/realms/pravidhi
```

OIDC discovery:

```
https://mcp.pravidhisolutions.in/auth/realms/pravidhi/.well-known/openid-configuration
```

JWKS:

```
https://mcp.pravidhisolutions.in/auth/realms/pravidhi/protocol/openid-connect/certs
```

Protected-resource metadata:

```
https://mcp.pravidhisolutions.in/.well-known/oauth-protected-resource
```

## OAuth flow

The reference ChatGPT integration uses authorization code flow with PKCE S256.

The pre-registered ChatGPT client is:

```
https://chatgpt.com/oauth/client.json
```

Callback:

```
https://chatgpt.com/connector_platform_oauth_redirect
```

The authorization server must accept the scopes requested by the client, including standard OIDC scopes such as `openid` and `offline_access`, plus the Pravidhi scopes.

## Pravidhi scopes

- `pravidhi.read` — authenticated read capabilities
- `pravidhi.execute` — authorized execution capabilities
- `pravidhi.admin` — administrative capabilities

Scopes are not a replacement for RBAC. The control plane must apply tenant and role policy after token validation.

## JWT validation

The MCP resource server validates:

- JWT signature
- signing-key `kid`
- issuer
- resource audience
- `exp`
- `nbf`
- required scopes

The resource audience is:

```
https://mcp.pravidhisolutions.in
```

Tokens that fail validation must not reach protected tool execution.

## Control-plane identity

The control plane can use trusted OIDC claims for tenant and role context.

Tenant claims may include:

- `tenant_id`
- `org_id`
- `organization_id`

Role context may include:

- `roles`
- `realm_access.roles`
- `scope`

These claims must be accepted only after the token's issuer, signature and audience have been validated.

## Role mapping

The reference realm defines:

- `pravidhi-user`
- `pravidhi-operator`
- `pravidhi-admin`

Recommended policy:

| Capability | Required scope | Role |
|---|---|---|
| Read | `pravidhi.read` | user/operator/admin |
| Execute | `pravidhi.execute` | operator/admin |
| Admin | `pravidhi.admin` | admin |

The actual control-plane policy is authoritative.

## Application sessions

The control plane may also establish an HttpOnly, Secure session cookie for browser-based application login.

Treat sessions as bearer credentials and invalidate them on logout.

## Secrets

OAuth client secrets, Keycloak admin credentials, signing keys, bearer tokens and production environment files must remain outside Git.

Use `.env.example` to document configuration shape without values.
